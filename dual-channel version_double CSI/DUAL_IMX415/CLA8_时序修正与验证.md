# CLA8 时序修正与手动布局布线说明

工程：`dual_imx415_gray_demo.al`；top：`dual_imx415_top`；器件：PH1A90SEG324-2；TD：2026.1 SP2；硬件版本寄存器：0x434c4138（CLA8）。原 CLA7 工程及其布线结果保留在 DUAL_IMX415_RTL_OPT4_20261028。

## 最新报告为什么仍有违例

本轮依据 CLA7 在 2026-10-28 19:42:09 生成的 `final_timing.rpt` 和 `route.qor`：setup WNS -0.128 ns，TNS -0.478 ns，14 个违例端点；hold WNS +0.020 ns，无违例。Slice 61025/64320（94.88%），ERAM 248/272，DSP 115/240，STA 覆盖 99.76%。上轮 JPEG 输出背压和行调度长路径已不在该报告的负裕量列表，但另有以下路径：

| 路径 | 最差裕量 | 具体证据及处理 |
|---|---:|---|
| 编码输入握手到 JPEG 输入 FIFO RAM 读使能 | -0.128 ns | 路径 4.753 ns，其中布线 4.236 ns，占约90%；本版隔离消费者 ready 与 RAM 使能 |
| SGDMA 地址到 C2H 寄存器 | -0.073 ns | 加密 IP 内部，最大扇出667，约89%延迟来自布线；不能在不可读的 IP 内随意插拍，需由物理高扇出优化及新布线验证 |
| CLAHE 模式信号到乘法器 | -0.023 ns | 6级逻辑，最大扇出137；本版未修改，需在新布线报告重新检查 |
| JPEG 写横坐标计数终止控制 | 约-0.023 ns | 本版未修改，需在新布线报告重新检查 |

总负裕量下降不等于已收敛。当前布线密度很高，修改一处会改变其他路径布局；不能将综合通过或逻辑级数少当作时序通过。

## 本版修改

给已有 `v2_async_fifo` 加参数 `READ_REFILL_ON_POP`，默认1保持原行为，仅 JPEG 输入 CDC 启用0。启用后，输出寄存器空时才读 RAM；在同拍消费现有输出时不立即从 RAM 补入，因此下游 ready 不再组合地传递到 RAM 读使能及读指针更新。

该模式最多每2个编码时钟补入一组；JPEG 串行器每4个编码时钟消耗一组，理论补入能力仍高于需求。启停、空队列及背压解除时的实际开销由完整编码测试验证。没有新增图像 RAM，没有改变真实时钟频率和时序约束。

## 用户手动布局布线

完成本版正式综合后，直接打开本目录工程，手动执行 Optimize Placement → Optimize Routing → Generate Bitstream。助手不会主动启动物理流程。

可选：在TD Tcl Console执行 `source tools/manual_physical_settings.tcl`，设置TD上一轮QoR报告建议的高扇出及布线后优化力度，再手动启动物理流程。该脚本本身不会启动任何run，会增加物理优化耗时，不能保证闭合。

完成后检查setup/hold及覆盖范围，并保留 `phy_1/final_timing.rpt`、`route.qor`、`*_chk.timing` 和 `run.log`。本版当前没有新位流、没有新布线结果，不能宣称时序收敛或上板稳定。
