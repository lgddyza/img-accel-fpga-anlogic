# 双路 FPGA 时序优化与验证

## 工程边界

- 工程入口：`dual_imx415_gray_demo.al`；顶层 `dual_imx415_top`；器件 PH1A90SEG324-2；TD 2026.1 SP2。
- 本工程复制自 `DUAL_IMX415_RTL_OPT6_20261028`（CLA9），原工程及物理报告保留。两路采集、DDR 帧存、三条带 JPEG、PCIe 和 RK 控制 ABI 沿用该基线。
- 为兼容现有 RK/PC 软件，硬件版本寄存器仍返回 `0x434c4139`。它无法区分本工程与旧 CLA9 位流；用户生成新 bit 后，应记录实际文件路径、时间和 SHA256，不能只凭寄存器识别版本。
- 本工程不包含新 bit；综合、仿真、布局布线、板测是不同验证阶段。

## 基线和分析

CLA9 布线结果：setup WNS +0.231 ns，hold WNS +0.008 ns，STA 覆盖率 99.74%。Slice 56313/64320，ERAM 256/272。JPEG Huffman、CLAHE 行权重和 PCIe DMA 分别是相关时钟域较紧路径；对应最差路径的数据网络延迟占比约 70%、58%、82%。这些数据来自基线，不能作为本工程的布线结果。报告中综合产生的实例名称可能不对应信号原有功能，应根据实际网络和起终点判断。

## 本轮修改

1. 黑帽仍执行 3×3 闭运算，计算 `response=max(close-gray,0)`，输出 `max(gray-response,0)`。不再实例化四方向长度5的开运算、32位方向窗口及其原图对齐队列。硬件模式号保留，黑帽叠加 CLAHE 的选择也保留。
2. 这一黑帽版本与旧版方向滤波黑帽**不等效**，可能更明显地增强路面斑点和纹理。相同输入时，高斯和灰度没有被更改。保留未实例化的方向滤波源码供后续研究。
3. CLAHE 纵向插值权重改为在有效行末计算下一行权重并寄存；帧首重置权重为0。保留原有权重公式、舍入、吞吐、相机独立状态和模式接口。
4. 未改变 DDR 乒乓、JPEG 缓存深度或 PCIe IP 参数；未新增需要 TD 登记的生产 RTL 源。

## 已执行仿真

- 64×24 输入暂停：灰度、高斯各强度、黑帽、黑帽叠加 CLAHE 首帧旁路，逐像素及原始 OBS1 特征、帧行标记和帧首锁定通过。
- 1920×1080：高斯和新黑帽各一帧，1036800 个四像素组逐像素对照通过，包含原始特征与帧行标记。
- CLAHE 新旧模块对照：64×32 和 8×1080，五帧随机输入、连续行及输入暂停，输出像素、握手标记、统计状态一致。8×1080 覆盖 1080 行权重计算；不是1920×1080逐像素对照。
- 两路 CLAHE 完整 1920×1080：6帧，3110400 个四像素组，输出数量与标记正确、两路统计错误为0。该测试不等同于逐像素新旧比较。
- JPEG CDC 及黑帽行缓存信用测试通过。

## 时序手册参考与后续实验

本机安路 `TD_User_Guide_V6.2.pdf` 的物理选项部分说明：`pack_effort` 低值可能缓解拥塞但需要更多 Slice；`hfn_opt_effort` 提高可能增加资源；`macro_performance` 提供 DSP/RAM 线长及关键路径选项。手册的 PH1A 策略表还列出 `MacroTiming`、`CongestionMedium`、`CongestionHigh`，并说明布局和布线结果可能波动。这些是厂商对工具策略的说明，不证明某个选项对本设计有效。

本轮优先通过减少黑帽宽窗口和寄存 CLAHE 权重改善结构，不修改时钟频率、约束或物理策略。手动布线后先对比本工程和 CLA9 的 setup/hold WNS、TNS、最差路径及 net/cell 延迟、Slice 和 ERAM。若仍有违例，依次单独尝试拥塞策略、宏资源相关策略和高扇出优化；每次只改变一个设置，并保留完整报告。不要使用错误的时序例外掩盖路径，也不要以综合 WNS 替代布线结果。

在线检索时 AMD 页面仅返回 JavaScript 加载页，Intel 页面超时；不能把未经核验的在线资料当作本次结论。安路资料为本机安装手册，并非独立的效果试验。

## 正式综合结果

2026-10-30 通过 TD GUI 的 `launch_runs syn_1 -step opt_gate` 完成 Read Design、RTL 综合和门级映射，三个阶段均有工具生成的完成标记；运行日志确认新黑帽和 CLAHE 模块已展开。124 项工程登记与本次生成的 `.prj` 核对无误，128 项输入哈希在综合期间保持不变。
