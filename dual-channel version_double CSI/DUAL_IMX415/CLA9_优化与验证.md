## 结构修改

| 部分 | 修改及目的 |
|---|---|
| CLAHE 直方图 | 将 capture 与生成映射阶段的读地址合并为一个明确的同步读端口，将清零与累加合并为一个写端口，配合 TD 的 BRAM 映射属性。两路相机的统计状态保持独立。 |
| CLAHE 前后 | 增加输入选择后、输出选择后的寄存器，隔开增强模式选择、RAM 地址及下游控制组合逻辑。像素与 SOF/EOL/valid 同步增加 2 个时钟周期的延迟。 |
| JPEG 输入 FIFO | 增加可选写指针预计算，提前保存 wp+1；full 引起的 push 判定只选择指针，避免再串联进位链。其他实例默认行为保持原样。 |
| DDR 读 FIFO | 启用读指针预计算及禁止消费同拍补入；消费者每 2 个时钟取一字，FIFO 的补入能力与之匹配，减少 ready 到 RAM 使能及指针的组合传播。 |
| PCIe 诊断读回 | 48 字数据分为三组 16 字，先锁存候选结果再选择 AXI-Lite 返回值。读响应增加 1 个时钟周期，保留 AR 接受时取快照及背压保持语义。 |
| Huffman 负幅值 | 用绝对值的前缀 OR 和按位取反直接形成 JPEG 负幅值，替代类别、移位及加法串联。没有增加编码状态或编码周期。 |

CLAHE 的分块、256 个灰度桶、裁剪、插值、时间平滑及各相机状态未作近似简化。预处理模式、强度、QF 和诊断页 ABI 保留，版本号更新为 CLA9。相机配置、引脚和时钟约束与 CLA8 一致。

首次尝试只添加 RAM 属性时，TD 报无法匹配 writemode，仍生成分布式 RAM。首轮日志和资源报告保留于 `build/cla9_inference_attempt1`。改为明确的一读一写结构后，使用 TD 的 `reset_runs syn_1 -f` 和正常 `launch_runs` 重新完整综合；最终日志没有该 RAM 映射失败提示。

## 验证结果

- 双路 1080P CLAHE：6 帧，共 3110400 个四像素组，输入输出数量、帧行标记正确，两路各完成 2 次学习，无统计错误。
- CLAHE 小尺寸验证：全部 LUT 项与各相机历史一致，两路不同输入产生独立的映射。
- 预处理参考对照：灰度、高斯各强度、黑帽、暂停输入、帧开始锁定模式及原始 OBS1 特征逐像素通过；CLAHE 首帧预热与模式切换另行通过。
- FIFO：异步时钟、随机背压、满空切换、指针多次回绕、非空复位通过，两种读补入设置分别完成 1353、1357 个有效数据的最终轮验证。
- JPEG CDC：4:1 序列化、帧行标记、背压、非空复位及连续 128 像素输出通过。
- Huffman：实际 RTL 的负幅值网络对绝对值 0..2047 全范围与原数学公式相等。
- 1920x48 真实编码：4 帧、主机暂停与背压通过。
- 1920x1080 真实三条带 JPEG：两帧服务时间 7.21702875 ms、7.21473375 ms，在该输入和无主机背压条件下满足共享编码池每帧 8.333333 ms 的双路 60 FPS 预算。这是仿真结果，不是整机板测帧率。
- 六张 JPEG 均可解码为 1920x360，且六张都与 CLA8 输出逐字节一致。
- DDR 帧存储：随机 AXI 背压、槽位压力、相机停止与恢复、写错误保护通过；1080P 同时到达的双路源及生产 FIFO 深度测试通过。测试使用理想/行为 AXI，不能替代真实 DDR 仲裁测量。
- 行缓存信用管理：容量、同拍事件、条带切换、跨帧及故障检查通过。
- AXI-Lite：AW/W 错位、WSTRB、QF/模式参数、冻结诊断页、R 通道暂停保持及 DDR 停钟/复位场景通过。
- 配套软件的控制与状态 16 项回归通过，CLA9 可执行上位机和 RK payload 已重新打包，尚未连接板卡部署。
